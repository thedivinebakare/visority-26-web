# Existing CATER coupon cap implementation

Goal: preserve CATERSTUDIOS at 50% off and enforce 20 lifetime successful uses.

Architecture: existing Apps Script backend serializes ledger operations using
LockService. Vercel reserves before Paystack initialization and commits only
verified live payments. Existing payable sessions occupy capacity. A local clock
alone never releases a reservation.

Constraints: no new coupon, database, checkout design, or unrelated changes.

- [ ] Add a deterministic ledger state machine and exercise the 19/20 boundary,
  duplicate references, active holds, failure release, and late-payment guard.
- [ ] Wrap it in an authenticated Apps Script handler with a script-wide lock,
  durable storage, strict schema validation, and a deployment protocol handshake.
- [ ] Add server-only ledger client and payment verification reconciliation.
- [ ] Wire coupon validation, checkout initialization, verification and webhook.
- [ ] Keep full-price checkout independent of ledger availability; clear stale
  frontend discounts on exhausted responses using the existing feedback element.
- [ ] Resolve account-wide timeout and manual coupon policy before activation.
- [ ] Deploy the Apps Script backend, seed verified history without resets, then
  deploy the Vercel payment changes and verify production.

Verification: run `node qa-coupon-cap.cjs`; production rollout requires actual
backend deployment access and provider expiry assurance for old and new sessions.
Do not substitute an in-memory test for proof of a deployed distributed lock.
